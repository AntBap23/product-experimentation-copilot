# Fieldwork Supply backend upgrade

The persistent version is authored in `public/store/`, with same-origin API routes
in `app/api/` and shared server code in `lib/platform/`. The existing `dist/` is
now generated framework output. Do not edit it.

Run `node ../../scripts/configure_apps.mjs`, `node build-analytics.mjs`, and
`npm run dev -- --port 3001` after configuring the ignored root environment file.
Read [platform setup](../../docs/platform_build.md) before deploying. The existing
live static storefront is retained until the Supabase-backed version is verified.

# Fieldwork Supply demo storefront

The website source lives in `dist/`. Edit the catalog and event triggers in
`dist/shop.js`, page content in `dist/index.html`, and styling in `dist/style.css`.
Sites hosts this folder as a static website. Updates are published to the same Site.

To preview locally from this folder, run `python3 -m http.server 8080 --directory dist`
and open http://localhost:8080.

## Verify collection

Use **Demo sign in** to choose one of six fictional shoppers. Each has a stable
`fieldwork-demo-*` ID passed to PostHog `identify`, so repeat visits as the same
shopper reuse that profile. This is a browser-only simulation, not authentication
or access control. It collects no passwords. The selected shopper persists across
reloads in the current tab via sessionStorage.

Switching shoppers or signing out calls PostHog `reset` and clears the bag and
checkout. Sign-out is captured under the departing shopper; subsequent guest
events use a fresh anonymous identity. Events include `is_demo`, `auth_status`,
and, when signed in, `demo_user_id`. Login/logout events are named
`demo_signed_in` and `demo_signed_out`. The hosted Site's ChatGPT access gate
is separate from these fictional shopper profiles.

Open the site with `?utm_source=newsletter&utm_medium=email&utm_campaign=trail_demo`
and click through a purchase. Open **Analytics event log** at the bottom to see
the events generated by the page. Reloading starts a new demo session and clears
the log and bag. No payment details are collected.

| Event | Trigger |
| --- | --- |
| `$pageview` | Storefront opens |
| `view_item` | Product detail opens |
| `add_to_cart` | Shopper adds an item |
| `remove_from_cart` | Shopper removes an item |
| `begin_checkout` | Checkout opens with items in the bag |
| `add_payment_info` | Shopper selects the simulated payment method |
| `purchase` | Shopper confirms a simulated order |

A checkout attempt shares one `checkout_id` across its events. Test a completed
order and an abandoned checkout. If campaign tags are present, the storefront
copies them to each event. Storefront events carry `data_source=demo_store`.

## PostHog configuration

Copy `.env.example` to `.env` and set `POSTHOG_PROJECT_TOKEN` and
`POSTHOG_HOST` from the target project's settings. Run `node build-analytics.mjs`
before previewing or publishing. This generates the browser's public configuration
in `dist/analytics-config.js`; both it and `.env` are excluded from Git.
The generated configuration ships in the static deployment.

`analytics.js` initializes the official browser SDK before `shop.js` and queues
events while it loads. Automatic pageviews, pageleaves, autocapture, and session
recording are disabled; the storefront sends its explicit pageview once.
Complete a simulated checkout and inspect PostHog Activity for the matching
events and shared `checkout_id`. Preview traffic also reaches this project;
use the event's URL/host to distinguish localhost from the deployed storefront.

[PostHog JavaScript SDK](https://posthog.com/docs/libraries/js)
